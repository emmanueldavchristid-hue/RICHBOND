# Plan d'exécution – LOT-03 Référentiels

Branche : `lot/03-referentiels`. Exigences : EX-10, EX-11. Dépend de LOT-01 (`withAction`, `requirePageAction`, `audit.log(tx, …)`, `StatusBadge`, `PageHeader`, `EmptyState`, `NativeSelect`) et LOT-02 (`requireWritable`, `WriteButton`, `useLicense`).
Prépare LOT-04/05 (DA/BC : article, fournisseur, dépôt, service, devise + taux), LOT-07 (onglet Stock), LOT-08/09 (codes = codes Sage, import initial).
**Ne jamais lire `.env*`.** Aucune suppression physique : tout passe par un statut ou `active=false`.

## Choix retenus (option prudente)
| # | Choix | Raison |
|---|---|---|
| R1 | Un seul champ `code` (unique, majuscules, `^[A-Z0-9][A-Z0-9._-]{0,16}$`, 17 car. max = limite Sage tiers/articles) = code Sage s'il existe. Vide à la création → généré côté serveur `ART-00001` / `FRS-00001` via `Counter` (année `0` = non annuel) dans la transaction | Correspondance Sage (LOT-08) sans double code ; unicité garantie en concurrence |

## Schéma Prisma (migration `referentiels`)
Enums : `ItemCategory` (MATIERE_PREMIERE, INTRANT, PDR, FOURNITURE, SERVICE), `Criticality` (CRITIQUE, IMPORTANT, STANDARD), `ItemStatus` (ACTIF, BLOQUE, OBSOLETE), `SupplierType` (LOCAL, IMPORT), `SupplierStatus` (ACTIF, EN_EVALUATION, BLOQUE), `PaymentTerm` (COMPTANT, J30, J45, J60, J90, FIN_DE_MOIS_30, AUTRE), `Incoterm` (EXW, FCA, FAS, FOB, CFR, CIF, CPT, CIP, DAP, DPU, DDP), `PriceSource` (MANUEL, BC, FACTURE).
Modèles (`@@map` snake_case, `createdAt/updatedAt`, `createdById` partout) :
- `Warehouse` (code @unique, name, active) · `Department` (code @unique, name, active)
- `Currency` (code @id ISO 3, name, symbol, decimals Int, isBase Boolean, active) · `ExchangeRate` (currencyCode, date @db.Date, rate Decimal(14,6), note?, createdById ; @@unique([currencyCode, date]))
- `Supplier` (code @unique, name, type, country (ISO 2, défaut CI), city?, currencyCode, ncc? @unique, rccm?, paymentTerm, paymentTermNote?, incoterm?, leadTimeDays Int?, categories ItemCategory[], status, blockedReason?, blockedAt?, blockedById?, notes?) ; @@index([status, type]), @@index([name])
- `SupplierContact` (supplierId, name, role?, phone?, email?, isPrimary, active)
- `Item` (code @unique, name, category, family?, stockUnit, purchaseUnit, conversionFactor Decimal(14,3) @default(1), stocked, criticality @default(STANDARD), abcClass String? (calculé LOT-07), defaultWarehouseId?, safetyStock/reorderPoint/economicOrderQty Decimal(14,3)?, leadTimeDays Int?, mainSupplierId?, barcode? @unique, status, equipment?, photoPath?, notes?) ; @@index([category, status]), @@index([criticality]), @@index([name]), @@index([equipment])
- `ItemSupplier` (itemId, supplierId, supplierRef?, lastPrice Decimal(14,2)?, currencyCode?, lastPriceDate?, leadTimeDays?, minOrderQty Decimal(14,3)?, active) ; @@unique([itemId, supplierId])
- `ItemPriceHistory` (itemId, supplierId, price Decimal(14,2), currencyCode, rateToXof Decimal(14,6)?, source, sourceRef?, date, createdById) ; @@index([itemId, date])
- `Setting` (key @id, value Json, updatedById?, updatedAt)
Recherche insensible à la casse : `contains` + `mode: insensitive` (index trigram reporté, à revoir après import Sage).
