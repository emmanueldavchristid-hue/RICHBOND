## Schéma Prisma (migration `demandes_achat`)
Enums : `PurchaseRequestStatus` (D1), `PurchaseRequestUrgency` (D5), `PurchaseRequestType` (D6), `PurchaseRequestKind` (`STANDARD, REAPPRO`), `PurchaseRequestEventType` (`CREATED, UPDATED, SUBMITTED, RESUBMITTED, APPROVED, REJECTED, RETURNED, CANCELLED, ASSIGNED, QTY_CHANGED, COMMENT, ATTACHMENT_ADDED, ATTACHMENT_REMOVED, STATUS_SYNC`), `NotificationSeverity` (`INFO, IMPORTANT, CRITIQUE`).
- `PurchaseRequest` : number? @unique, status, kind, urgency, priority Int, type, departmentId, requesterName (texte libre, 2–100), reason (5–1000), neededBy @db.Date, estimatedTotal Int?, createdById, submittedAt?, approvedAt?, approvedById?, rejectedReason?, cancelledReason?, cancelledAt?, cancelledById?, assignedBuyerId?, version via updatedAt ; `@@index([status, priority, neededBy])`, `@@index([createdById])`, `@@index([assignedBuyerId, status])`, `@@index([departmentId])`.
- `PurchaseRequestLine` : requestId, lineNo Int, itemId?, freeDesignation?, quantity Decimal(14,3) (= demandée), approvedQty Decimal(14,3)?, unit String, stockQty Decimal(14,3)?, estimatedUnitPrice Int?, note? ; `@@unique([requestId, lineNo])`, `@@index([itemId])` ; CHECK SQL `item_id IS NOT NULL OR free_designation IS NOT NULL` dans la migration.
- `PurchaseRequestEvent` : requestId, type, userId, fromStatus?, toStatus?, comment?, payload Json?, createdAt ; `@@index([requestId, createdAt])`.
- `PurchaseRequestAttachment` : requestId, fileName, mimeType, size Int, path, uploadedById, createdAt, removedAt?.
- `Notification` : recipientId, type String, severity, title, body?, link, entity?, entityId?, readAt?, createdAt ; `@@index([recipientId, readAt, createdAt])`.
